# Ekza Studio v0.7.0 — one studio, two layouts (draft)

Status: **draft release notes**, written at the T12 integration (branch `halo/t12-release`, 2026-10-25). Not tagged,
not merged to `main`, not deployed: the merge, the tag and the deploy are the owner's, after the real-iPad run
(the last open item of the release gate, below). Earlier releases recorded only a one-line tag message
(`git tag -n v0.6.1`); this file is the first release-notes page, and the tag message can be its title.

Proposed tag message: `v0.7.0: Ekza Studio's Simple layout (beta), AI generation and clean-up, the character contract`.

## Highlights

- **Ekza Studio is one studio with two layouts.** The new **Simple layout** (touch-first and Pencil-first, the front
  door at `/app`) and **Ekza Studio Pro** (the docked, hotkey-driven layout you know, at `/editor`) open the same
  project with the same undo history; one tap switches between them on the same page. Auto-Rig stays as *Rig a model
  for me*. The Simple layout is **beta** (Help › About says so).
- **Touch anything, and what you can do with it appears next to it**: up to six plain verbs, ⋯ More for every
  operator with its Pro name and hotkey, search for everything, and the Path *Make · Paint · Rig · Animate → Share*
  with one list of checks behind it.
- **Animation first**: a timeline in frames with a tick on every frame, Rec on by default, the Animations row to
  switch cycles in one tap, Keys and Curves by touch and Pencil, *Reach* posing (drag a hand and the arm follows),
  the CC0 library, History with *Undo all* for AI runs.
- **The turnkey pipeline**: words or a photo → a generated model through your own gateway → *Clean up for a game*
  in one step → *Rig it* on the same canvas → animate → *Share* to OMOBA & Ekza Space, a game engine or just the
  animations, byte-equal to Pro and Auto-Rig.
- **iPad**: Safari 26+ on iPad is supported for the Simple layout — the Pencil's pressure paints weights, palms are
  ignored while the Pencil works, *Export … to Files* and *Save project to Files* are two taps each, a reload resumes
  silently where you were (camera included).
- **Games**: Studio reads a game's contract (OMOBA's, bundled), shows every slot of its kit with a status and a fix,
  and writes the **OMOBA hero package** (VRM 1.0 with your animations and `ekza_package_v1`).

## What changed

### The entry and the names

- A first visit to `/` opens Ekza Studio's Home on every device; a remembered choice still wins (`studio` → Pro,
  `autorig` → Auto-Rig); `/?chooser=1` lists **Ekza Studio**, **Ekza Studio Pro** and **Rig a model for me**. Deep links
  never redirect. Blocked or malformed storage counts as a first visit.
- Studio is titled **Ekza Studio Pro** (menu bar, page title). Its status line has **▤ Simple layout**, and File › and
  Help › *Switch to the Simple Layout*; using the switch updates the remembered entry. Arriving from the Simple layout,
  Pro says *Same project, every panel at once · Undo still works*.
- Preferences › Start in: *Default (Ekza Studio) · Ekza Studio · Ekza Studio Pro · Rig a model for me*.

### Ekza Studio's Simple layout (new, beta)

- Home: Continue cards, *Try a sample*, *Bring a model* (the file's bytes decide what it is), *Make a character*
  (templates, and *Create with AI* where a gateway is enabled), *Rig a model for me*, ▤ Pro layout. No modal on first
  open.
- Input: the Pencil makes, fingers move the view; the Thumb key (one on-screen Shift that carries every modifier);
  the Loupe for crowded picks; double-tap frames; two-finger tap undoes; *Reduce gestures*; with a mouse and keyboard
  it works too (right-click opens the verbs).
- Make: clean-up first for imported and generated models (*Clean up ▾* for a game in two touches, *Reduce ▾*,
  *Separate*), *New shape ▾*, *Mirror edits*, the extrude cap handle, reference planes. On a phone the selection level
  folds into one chip.
- Paint: swatches in the tray, *Finish ▾* Matte · Shiny, *Fill part*, *Pick colour*.
- Rig: *Rig it for me* on one card (the destination, the finger detail, the story line, a motion test, the starter
  set) — the same operator log as Auto-Rig ①–⑤; *Adjust dots* in front and side panes; weights with Pencil pressure,
  *Who owns this?*, *This area follows*, the bend test (*Fix where it bends badly*); Checks, Bones and Weights sheets.
- Animate: the Thread (frames by default, seconds in Settings › Time), the Animations row, + New (30 / 60 / 100
  frames), Keys and Curves layers, Reach, the Library, History (↶'s long-press), *Ask AI* with a live activity line
  under the search pill (an agent works from a computer in Chrome or Edge; on the iPad an honest card and the
  recipes).
- Share: destination first, its checks with fixes, *Export … to Files*, *Save project to Files*, the iPad share sheet.
- Accessibility: 44 pt targets, 16 px inputs, named dialogs, announced selections; axe (WCAG 2.2 AA) clean in the gate.

### AI generation and model clean-up (new)

- Clean-up operators, local and key-free: *Clean up for a game* (`mesh.intake`, one undo step), Reduce (to a triangle
  budget, seams never crack), Normalize, Palette Bake, Downsize Textures — Pro's Mesh menu and the Simple layout's
  *Clean up ▾*.
- A self-hosted generation gateway with adapters for two text/image-to-3D services, a token and spend caps; off by
  default (a server build answers 404 until `GEN_GATEWAY_ENABLED=1`; a static build needs a gateway URL at build time).
  Self-hosting guide: [ai-generation.md](../ai-generation.md).
- Pro: File › *Generate with AI…*; the Simple layout: Make › *Create with AI*. Words or a picture (re-encoded, no
  metadata), size presets, the service's terms, the plan and the price before anything is spent, jobs with progress,
  *Bring it in* cleaned, then *Rig it* (one touch into the Rig-it card).
- Exports record the generator (`ekza_model_v1.provenance.generator`); results carry a *Made with AI* badge.

### The character contract (new)

- Studio reads `ekza.game-contract.v1` (OMOBA's contract bundled and pinned), binds a character to a game target,
  and shows the whole kit with statuses, timing and fixes: Pro's **Target** panel, Auto-Rig ④ *For a game…*, the
  Simple layout's Share › OMOBA.
- The **OMOBA hero package**: a VRM 1.0 with your animations and `ekza_package_v1` (profile `ekza/omoba-humanoid-v2`),
  byte lints, named timeline markers, a developer zip. Contract data and schemas are CC0 (LIC-1).

### Platform

- One 5,000,000 B size gate on every route (`/editor`, `/autorig`, `/app`; the owner's SIZE-1); the lazy boundaries
  still keep each layout's code out of the others.
- The DEV contour of the hosted editor is marked (DEV badge, titles, noindex).
- The local gate now runs Chrome with touch at iPad sizes (CDP multi-touch and Pencil) and WebKit as an iPad
  (compatibility), and axe over the Simple layout's sheets.

## Known limitations

- The Simple layout is beta; its real-iPad run is pending (above). Phones work but are best-effort.
- The AI agent (MCP) cannot reach an iPad tab (no loopback from WebKit): pair on a computer ([agents.md](../agents.md)).
- Live generation providers have not been exercised end to end (the acceptance runs against mock providers); keys and
  the hosted gateway are the owner's. A provider's own rig is not editable yet (`char.makeEditable`).
- Not built in this release: a recipe stepper card with *Resume*, Numbers pinned beside the curves on wide screens, the
  *Open in a new tab* hand-over from the Simple layout, the ⟨Bend joint⟩ scrub chip, Russian strings.
- The About dialogs show the kernel's `EDITOR_VERSION` (`0.2.0`, unchanged since M2a and written into exports and
  autosaves); bumping it is a release step for the owner (it changes export metadata).
